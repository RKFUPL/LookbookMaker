# RK Lookbook Maker

RK Lookbook Maker is a Next.js catalog studio and custom PDF flipbook viewer for Rashi Kapoor. New uploads are stored as PDF files in persistent server storage; MongoDB stores only catalog and storage metadata.

## PDF storage

New catalog imports use local storage as the primary source:

```text
Admin PDF upload
  -> generated storage key under LOOKBOOK_STORAGE_DIR
  -> MongoDB catalog metadata
  -> /api/catalogs/:id/pdf (authenticated draft or published catalog)
  -> PDF.js viewer
```

The storage key is generated by the server and never uses the submitted filename as a path. The PDF route validates that the resolved file remains inside the configured directory, verifies the `%PDF-` signature, and supports `GET`, `HEAD`, and single byte-range requests. Existing WorkDrive and external-URL catalogs continue to use their compatibility paths. They are not migrated or deleted automatically.

## Local development

Prerequisites: Node.js 22+ and MongoDB.

```powershell
npm install
npm run dev
```

The development server is at `http://localhost:3002`. Keep that terminal open while using the app.

Set `MONGODB_URI`, `AUTH_SECRET` (at least 32 characters), and `APP_URL` in `.env`. Local PDFs default to `%USERPROFILE%\.lookbook-maker\pdfs`; set `LOOKBOOK_STORAGE_DIR` to use another absolute directory. `LOOKBOOK_MAX_UPLOAD_MB` defaults to 100. The browser and API both reject larger uploads.

Create a staff account with `npm run seed:admin`, then use `/admin/catalogs/new`. A PDF file is required; no external PDF URL is required for new catalogs. For a legacy catalog, open its edit page and use **Upload replacement** to attach a locally stored PDF.

## VPS persistent storage

Docker Compose mounts this host directory:

```text
/opt/apps/rashi-kapoor/lookbook-maker-storage/pdfs
```

into the container at:

```text
/data/lookbooks
```

The container receives `LOOKBOOK_STORAGE_DIR=/data/lookbooks`. To override the host location, set `LOOKBOOK_STORAGE_HOST_DIR` in the VPS Compose environment. Keep the host directory outside the repository so deployments do not remove uploaded files.

One-time VPS setup (the image runs as UID/GID 1000):

```bash
sudo install -d -o 1000 -g 1000 -m 0770 /opt/apps/rashi-kapoor/lookbook-maker-storage/pdfs
cd /opt/apps/rashi-kapoor/lookbook-maker
docker compose build
docker compose up -d
curl -fsS http://127.0.0.1:3001/api/health/storage
```

The health route returns a failure if the mounted directory is absent or not writable. NGINX must retain `client_max_body_size 110m` for the 100 MiB application limit. Back up both MongoDB and the host PDF directory together; catalog records and files form one logical dataset.

## WorkDrive compatibility

WorkDrive settings and server-side OAuth remain available for existing records and optional future use. New upload and viewer paths do not require WorkDrive. Do not remove WorkDrive environment values while older `sourceType: "workdrive"` catalogs still need to be viewed.

## Verification

```powershell
npm run typecheck
npm run lint
npm run test:local-storage
npm run test:pdf
npm run test:runtime
git diff --check
```

Static and mocked tests do not prove that a VPS volume is mounted. After deployment, upload a small PDF, publish it, open the public catalog, test page navigation, and verify a range response from `/api/catalogs/:id/pdf`.
